# Phase 10 — API Schema Specification

> Defines the structured data schemas that map council protocol v2 artifacts to
> a machine-readable, searchable, and serveable API surface.
>
> These schemas are DERIVED from the meeting-protocol.md and templates in
> `.jarvis/council/templates/`. They are not arbitrary — they represent exactly
> what the protocol produces, in the order it produces it.
>
> Canonical source: `.jarvis/council/meeting-protocol.md`
> Templates: `.jarvis/council/templates/*.md`

---

## Design Principles

1. **File-as-database**: The markdown files ARE the canonical store. The API schema defines what a structured reader/writer must accept and return.
2. **Composition over inheritance**: A Meeting Record composes Evidence, Position, Conflict, Agreement, Confidence, and Vote objects. No circular dependencies.
3. **Every field has a source**: No field exists that the protocol doesn't produce or consume.
4. **Provenance is non-optional**: Every evidence item traces its origin. Every claim references evidence. Every synthesis references claims.
5. **Confidence is computed, not vibes**: The schema encodes the formula inputs, not just the output.

## Schema 1: Evidence

> The atomic knowledge unit. Every claim in a council meeting traces to evidence.
> Maps to: `.jarvis/council/templates/evidence.md`

```yaml
Evidence:
  id: string              # Scoped to meeting: "EVD-001"
  meeting_id: string      # Owning meeting: "MEETING-20260911-001"

  # What it is
  description: string     # Free-text description of what this evidence states
  type: enum              # One of 9 evidence classes (see EvidenceClass)

  # Where it came from
  source: string          # Provenance: what entity or location produced this
  source_type: enum       # Provenance type (see ProvenanceType)
  source_ref: string      # Optional: file path, URL, message_id, etc.

  # How reliable it is
  confidence: float       # 0.0–1.0, set at registration time
  verified: boolean       # Whether JARVIS has independently verified the claim

  # Logical dependencies
  based_on: string[]      # Evidence IDs this item reasons from (required if type=inference)

  # Lifecycle
  phase: enum             # "pre-meeting" (Phase 1, JARVIS-collected) or "in-meeting" (Phase 2, persona-generated)
  registered_by: string   # "jarvis" for Phase 1, "persona.<id>" for Phase 2
  registered_at: datetime # ISO 8601 timestamp

  # Relationships
  cited_by: string[]      # Position IDs that cite this evidence
  supports: string[]      # Conflict resolution option IDs this evidence supports
```

### EvidenceClass (enum)

| Value | Default Confidence | Phase | Description |
|-------|-------------------|-------|-------------|
| `user-testimony` | 0.90 | 1 | Direct user statement |
| `direct-observation` | 0.95 | 1 | JARVIS observed from filesystem or tool |
| `project-artifact` | 0.95 | 1 | From repo or vault files |
| `research-synthesis` | 0.75 | 1 | JARVIS combined multiple sources |
| `external-article` | 0.75 | 1 | Specific named external source |
| `web-search` | 0.60 | 1 | Unverified search result |
| `historical` | 0.75 | 1 | From past meetings or memory |
| `inference` | 0.65 | 1 or 2 | Logical reasoning from other evidence |
| `council-vm` | 0.70 | 2 only | Generated during council by a persona |

### ProvenanceType (enum)

| Value | Description |
|-------|-------------|
| `file` | From a file in the project (vault, repo, config) |
| `inference` | Logical reasoning from other evidence |
| `persona` | Generated by a council persona |
| `web` | From a web source |
| `meeting` | From a previous council meeting |
| `memory` | From JARVIS memory |
| `user` | From the user directly |
| `tool` | From a JARVIS tool (filesystem scan, etc.) |

## Schema 2: Position

> A single persona's reasoning output. Generated sequentially. Each persona
> sees only: the question, their own definition, and the evidence registry.
> Maps to: `.jarvis/council/templates/positions.md`

```yaml
Position:
  id: string              # Auto-generated: "POS-<meeting_id>-<persona_id>"
  meeting_id: string
  persona_id: string      # e.g. "persona.security-architect"
  persona_name: string    # Display name: "Security Architect"

  # Output
  vote: enum              # approve | reject | approve-with-conditions | abstain
  confidence: float       # 0.0–1.0, persona's self-assessed confidence
  reasoning: string       # One-line summary of core reasoning

  # Argumentation
  supporting_arguments: Argument[]
  counterarguments: Argument[]
  conditions: string[]    # What must be true for full endorsement (approve-with-conditions)

  # Epistemic hygiene
  assumptions: string[]   # Premises taken for granted (not in evidence)
  evidence_used: EvidenceCitation[]  # Links to evidence with interpretation

  # Reversal conditions — mandatory, every position must have ≥1
  reversal_conditions: ReversalCondition[]

  # Lifecycle
  activated_at: datetime  # When persona was loaded
  deactivated_at: datetime # When runtime.md was cleared
  phase: enum             # "pre-meeting" or "in-meeting"

  # Flags (set by JARVIS during synthesis)
  flags: string[]         # e.g. ["no-reversal-conditions", "low-evidence-count"]
```

```yaml
Argument:
  id: string              # "ARG-<meeting_id>-<N>"
  text: string            # The argument itself
  evidence_ids: string[]  # Supporting evidence (may be empty)
  strength: enum          # "strong" | "moderate" | "weak"  (JARVIS-assessed)
```

```yaml
EvidenceCitation:
  evidence_id: string     # "EVD-001"
  interpretation: string  # How this persona uses or interprets the evidence
```

```yaml
ReversalCondition:
  id: string              # "REV-<meeting_id>-<N>"
  condition: string       # Specific, observable condition
  threshold: string       # Quantitative or qualitative threshold
  currently_met: boolean  # Current state
  evidence_required: string  # What evidence would show the threshold is met
```

## Schema 3: CrossExamination

> Structured conflict analysis. Identifies material disagreements between positions.
> Mandatory when ≥1 material conflict exists.
> Maps to: `.jarvis/council/templates/cross-examination.md`

```yaml
CrossExamination:
  meeting_id: string
  conflicts: Conflict[]
  skipped: boolean        # True if no material conflicts found
  skip_reason: string     # "All positions reach the same conclusion"
```

```yaml
Conflict:
  id: string              # "CONFLICT-001"
  meeting_id: string

  # The disagreement
  disagreement: string    # What specifically they disagree on
  materiality: enum       # "high" | "medium" | "low"

  # Who disagrees
  positions_in_conflict: ConflictPosition[]

  # Evidence comparison — same evidence, different interpretation
  evidence_comparison: EvidenceComparison[]

  # Resolution options
  resolution_options: ResolutionOption[]

  # JARVIS assessment of which option is strongest
  jarvis_assessment: string
  strongest_option_id: string  # ID of the resolution option JARVIS judges strongest
```

```yaml
ConflictPosition:
  participant: string     # Persona name
  stance: enum            # Their vote on this specific point
  primary_evidence: string[]  # Evidence IDs they rely on
  core_reasoning: string  # One-line summary of their position on this conflict
```

```yaml
EvidenceComparison:
  evidence_id: string
  interpretation_a: string  # How the first party interprets it
  interpretation_b: string  # How the second party interprets it (or "not cited")
```

```yaml
ResolutionOption:
  id: string              # "A", "B", "C", etc.
  description: string
  supported_by: string[]  # Participant names
  type: enum              # "position" | "compromise"
```

## Schema 4: Agreement

> The quality of agreement classification. Raw vote counts are insufficient.
> Every position is classified into exactly one agreement category.
> Maps to: `.jarvis/council/templates/votes.md`

```yaml
Agreement:
  meeting_id: string

  # Classification groups
  full: AgreementGroup[]           # Same conclusion + same reasoning
  qualified: QualifiedGroup[]      # Same conclusion + different reasoning
  partial: PartialAgreement[]      # Agree on subset, disagree on rest
  disagreement: DisagreementGroup[] # Conflicting conclusions
  abstentions: AbstentionGroup[]   # No position taken

  # Summary counts
  summary: AgreementSummary
```

```yaml
AgreementGroup:
  id: string
  conclusion: string              # What they concluded
  participants: string[]          # Persona names
  shared_reasoning: string        # The reasoning they share
```

```yaml
QualifiedGroup:
  id: string
  conclusion: string
  reasoning_map: ReasoningEntry[]
```

```yaml
ReasoningEntry:
  participant: string
  reasoning: string               # Their unique reasoning for the same conclusion
```

```yaml
PartialAgreement:
  id: string
  agreed_items: PartialItem[]     # What they agree on
  disagreed_items: PartialItem[]  # What they disagree on
```

```yaml
PartialItem:
  description: string
  consensus: string               # e.g. "3/5 participants" or "no consensus"
  sides: string[]                 # Participants on each side (if disagreed)
```

```yaml
DisagreementGroup:
  id: string
  participants: string[]          # The disagreeing parties
  conflict: string                # What they disagree on
  evidence_for: string[]          # Evidence IDs supporting one side
  evidence_against: string[]      # Evidence IDs supporting the other side
```

```yaml
AbstentionGroup:
  participant: string
  reason: string                  # Why no position was taken
```

```yaml
AgreementSummary:
  full_count: integer
  qualified_count: integer
  partial_count: integer
  disagreement_count: integer
  abstention_count: integer
  total_positions: integer        # Positions actually generated (excl. abstentions)
  core_question_alignment: enum   # "unanimous" | "qualified" | "partial" | "split"
  implementation_alignment: enum  # Same scale, for implementation details
```

## Schema 5: ConfidencePropagation

> Weighted confidence calculation anchored to measurable inputs.
> Weights vary by meeting type.
> Maps to: `.jarvis/council/templates/conclusion.md`

```yaml
ConfidencePropagation:
  meeting_id: string
  meeting_type: enum              # Determines weights

  # Weight distribution (must sum to 1.0)
  weights: ConfidenceWeights

  # Component scores — each is 0.0–1.0 with a traceable calculation
  evidence_quality: ConfidenceComponent
  persona_convergence: ConfidenceComponent
  argument_strength: ConfidenceComponent
  counterargument_weakness: ConfidenceComponent

  # Result
  meeting_confidence: float       # Weighted sum
  confidence_label: enum          # VERY HIGH | HIGH | MEDIUM | LOW | VERY LOW
```

```yaml
ConfidenceWeights:
  evidence_quality: float
  persona_convergence: float
  argument_strength: float
  counterargument_weakness: float
  # Sum must equal 1.0. Values set by meeting_type or user override.
```

```yaml
ConfidenceComponent:
  score: float                    # 0.0–1.0
  weight: float                   # From ConfidenceWeights
  calculation: string             # Human-readable explanation of how the score was derived
  inputs: string[]                # Specific data points that fed the calculation
```

### Meeting Type → Default Weights

| Meeting Type | Evidence | Convergence | Argument | Counterarg. |
|-------------|----------|-------------|----------|-------------|
| `risk-assessment` | 0.50 | 0.15 | 0.20 | 0.15 |
| `strategic-direction` | 0.25 | 0.35 | 0.20 | 0.20 |
| `technical-decision` | 0.35 | 0.20 | 0.30 | 0.15 |
| `ethical-review` | 0.20 | 0.30 | 0.30 | 0.20 |
| `default` | 0.40 | 0.25 | 0.20 | 0.15 |

### Confidence Labels

| Range | Label |
|-------|-------|
| 0.85–1.00 | VERY HIGH |
| 0.70–0.84 | HIGH |
| 0.50–0.69 | MEDIUM |
| 0.30–0.49 | LOW |
| 0.00–0.29 | VERY LOW |

## Schema 7: MeetingRecord

> The root object. Composes all above schemas into a single coherent record.
> Maps to: `.jarvis/council/meetings/MEETING-YYYYMMDD-SEQ/`

```yaml
MeetingRecord:
  # Identity
  id: string                      # "MEETING-YYYYMMDD-SEQ"
  question: string                # The single question, verbatim

  # Classification
  meeting_type: enum              # risk-assessment | strategic-direction | technical-decision | ethical-review | default
  status: enum                    # planned | in_progress | complete
  created_at: datetime
  completed_at: datetime          # Null if in_progress

  # Participants
  participants: Participant[]

  # Evidence registry (composed)
  evidence: Evidence[]

  # Positions (composed)
  positions: Position[]

  # Cross-examination (composed)
  cross_examination: CrossExamination

  # Agreement classification (composed)
  agreement: Agreement

  # Individual votes (composed)
  votes: Vote[]

  # JARVIS synthesis
  synthesis: Synthesis

  # Confidence (composed)
  confidence: ConfidencePropagation

  # Recommendation
  recommendation: Recommendation

  # Reversal conditions tracker
  reversal_conditions: ReversalCondition[]

  # Flags
  flags: string[]                 # Protocol integrity flags
```

```yaml
Participant:
  persona_id: string
  persona_name: string
  domain: string                  # Why this persona was selected
  position_status: enum           # loaded | positioned | unloaded
  activated_at: datetime
  deactivated_at: datetime        # Null if still active
```

```yaml
Synthesis:
  text: string                    # JARVIS's integrated view (free-form)
  strongest_arguments: string[]   # Key supporting arguments, one per line
  strongest_counterarguments: string[]  # Key counterarguments, one per line
  cross_examination_resolution: string   # Which resolution option was chosen and why
  dissenting_views: string[]      # Preserved disagreements
```

```yaml
Recommendation:
  id: string                      # "council-recommendation-MEETING-YYYYMMDD-SEQ"
  text: string                    # The recommendation itself
  status: enum                    # "candidate" — ALWAYS candidate until confirmed
  evidence_ids: string[]          # Evidence that directly supports this recommendation
  type: enum                      # "council-recommendation"
```

## Schema 8: Decision

> The lifecycle from recommendation to decision. Council output never auto-becomes truth.
> Maps to: `.jarvis/council/decisions.md` + vault decisions

```yaml
Decision:
  id: string                      # "DEC-XXX"
  question: string                # The question that was decided
  recommendation_id: string       # Council recommendation that led to this
  meeting_id: string              # Source meeting

  # What was decided
  decision: string                # The decision text
  rationale: string               # Why this option was chosen

  # Lifecycle
  status: enum                    # candidate | active | superseded | deprecated
  authority: enum                 # user-explicit | decision-rule | council-auto (should never occur)
  authority_source: string        # Specific rule or user message that authorized this
  approved_by: string             # "user" or rule ID
  approved_at: datetime

  # Confidence (inherited from council)
  confidence: float               # From ConfidencePropagation.meeting_confidence
  confidence_label: enum          # Inherited label

  # Evidence
  evidence_ids: string[]          # Evidence supporting the decision
  reversal_conditions: ReversalCondition[]  # What would invalidate this decision

  # History
  created_at: datetime
  superseded_by: string           # DEC-XXX that replaced this, if any
  superseded_at: datetime

  # Links
  source_meeting_id: string
  vault_path: string              # Path in vault if persisted there
```

## Schema 9: KnowledgeFile

> Vault documents. The project's curated knowledge layer.
> Maps to: `vault/` directory structure

```yaml
KnowledgeFile:
  id: string                      # Auto-generated UUID or path-based ID
  path: string                    # Relative path in vault: "04 - Decisions/Active Decisions/DEC-001.md"
  filename: string                # "DEC-001 - Brand Palette.md"
  type: enum                      # decision | methodology | research | guide | log | meeting-summary | persona | template
  content_type: enum              # markdown | yaml | json | text

  # Metadata
  title: string                   # Human-readable title
  description: string             # Brief description
  tags: string[]                  # Searchable tags
  created_at: datetime
  updated_at: datetime
  author: string                  # "jarvis" | "user" | "council"

  # Content
  content: string                 # Full file content
  content_hash: string            # SHA-256 of content for change detection

  # Lineage
  source_meeting_id: string       # Council meeting that produced this, if any
  source_decision_id: string      # Decision that produced this, if any
  superseded_by: string           # Path of the file that replaced this, if any
  version: integer                # Incremented on each update

  # Relationships
  related_files: string[]         # IDs of related knowledge files
  referenced_by: string[]         # Meeting IDs or Decision IDs that reference this
```

```
GET    /api/meetings                            → MeetingRecord[] (list, filterable)
```

## Data Flow: Council Meeting → API

```
User: "Hold a council on X"
   │
   ▼
Step 1: Define question           → MeetingRecord.question
Step 2: Select participants        → MeetingRecord.participants
Step 3: Create meeting record      → MeetingRecord (status: in_progress)
Step 4: Collect evidence           → Evidence[] (Phase 1, registered_by: jarvis)
Step 5: Persona activation         → Position[] (each with evidence_used, reversal_conditions)
                                  → Evidence[] (Phase 2 additions, registered_by: persona.X)
Step 6: Cross-examination          → CrossExamination (Conflict[])
Step 7: Agreement classification   → Agreement (5-type taxonomy)
                                  → Vote[] (with agreement_category)
Step 8: JARVIS synthesis           → Synthesis
Step 9: Confidence propagation     → ConfidencePropagation (weighted formula)
                                  → Recommendation (status: candidate)
                                  → ReversalCondition[] (aggregated)
Step 10: Record and report         → MeetingRecord (status: complete)
   │
   ▼
User approves                      → Decision (status: active)
   │
   ▼
Knowledge persist                  → KnowledgeFile (vault document)
```

## Validation Rules

These are invariants the API MUST enforce:

### Evidence
1. `EVD-{N}` IDs are scoped to the meeting — not globally unique.
2. `inference` type MUST have non-empty `based_on`.
3. `council-vm` type MUST have `phase: "in-meeting"`.
4. Phase 1 evidence (`phase: "pre-meeting"`) has `registered_by: "jarvis"`.
5. Phase 2 evidence (`phase: "in-meeting"`) has `registered_by: "persona.<id>"`.
6. `confidence` is set at registration and is immutable (not recalculated).

### Positions
1. Every position MUST have ≥1 `reversal_conditions`. If empty, flag it.
2. `evidence_used` entries must reference valid evidence IDs in the same meeting.
3. `vote: "approve-with-conditions"` MUST have non-empty `conditions`.
4. `vote: "abstain"` MAY have empty `evidence_used`.
5. `confidence` is self-assessed by the persona — not computed.

### Cross-Examination
1. Each `Conflict` must have ≥2 `positions_in_conflict`.
2. Each `Conflict` must have ≥2 `resolution_options`.
3. At least one resolution option must be type `compromise`.
4. `jarvis_assessment` must name a `strongest_option_id`.

### Agreement
1. Every position must be classified into exactly one agreement category.
2. `AgreementSummary` counts must be consistent with the groups.
3. `core_question_alignment` is independent of `implementation_alignment`.

### Confidence
1. Weights must sum to 1.0 (±0.01 for floating-point).
2. All four components must be present.
3. `meeting_confidence` = Σ(component_score × component_weight).
4. `confidence_label` must match the confidence_scale table.

### Decisions
1. `status: "candidate"` is the only allowed initial status.
2. `status: "active"` requires `authority` and `approved_by`.
3. `status: "superseded"` requires `superseded_by`.
4. Decision confidence is inherited from the source meeting — not recomputed.
